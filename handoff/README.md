# MathRecord / MathMap — Balanced Research Handoff v5

## Purpose

This package is the recommended handoff for continuing the project after MathRecord Gates 0–1.

It deliberately combines two things:

1. **Research discipline:** the current coding assignment is a bounded representation-characterization study. It does not assume the final MathMap ontology is known.
2. **Intellectual continuity:** the richer mathematical ideas from the preceding research discussion are preserved as explicitly non-authoritative appendices so promising hypotheses are not lost merely because they are unproven.

The package therefore has three epistemic layers.

---

## Layer A — Evidence and current authority

Files `00`–`10` define the current research direction.

They determine what the coding agent may build now.

The strongest current claim is only:

> Gates 0–1 showed that a bounded set of Lean-native formal objects can be serialized faithfully and deterministically in the pinned environment.

The current task is to determine which candidate projections of real Lean mathematics are recoverable and useful enough to justify a future map/navigation system.

---

## Layer B — Research notebook

Files `11`–`15` preserve the deeper mathematical ideas:

- Curry–Howard and typed contextual states;
- named declarations as reusable actions;
- theorem interface versus certificate versus exact proof;
- hypergraph interpretations;
- selective opacity / zoom;
- contextual use events;
- mathematical importance and compression;
- alternative proofs and bridges;
- shared multi-role hypotheses;
- semantic overlays;
- failure modes and competing architectures.

These documents are **not authority**.

If an idea in Layer B conflicts with the evidence or with files `00`–`10`, the authoritative study design wins.

The coding agent may use Layer B to:

- propose candidate projections;
- design diagnostics;
- identify edge cases;
- record future hypotheses;
- interpret results.

It may not silently promote those ideas into permanent schema or scope.

---

## Layer C — Source evidence

The `source/` directory contains:

- the Gates 0–1 reports;
- the starting Gates 0–1 repository ZIP;
- the clarifying conversation that motivated the map/navigation hypotheses.

These are historical/evidentiary sources, not new implementation instructions.

---

## Current authorized work

Execute Phase 2A and Phase 2B only:

### Phase 2A — Real-corpus candidate representation study

Compare multiple projections of the same real Mathlib proof artifacts.

### Phase 2B — Contextual named-use event feasibility

Measure how precisely and completely meaningful theorem/definition use can be recovered.

Do not train a model yet.

Do not build a production ontology, polished storefront, universal mathematical graph, conjecture generator, abstraction inventor, or curation system.

A small diagnostic viewer is allowed only as a research instrument.

---

## Important supersession

The Gates 0–1 repository contains a historical recommendation to proceed directly to generic dynamic traces.

That recommendation is **superseded** by this package.

The new reason is not that dynamic traces are unimportant. It is that we first need evidence about the abstraction level we actually want to model.

Likewise, any earlier conceptual proposal that treats a declaration-centered AND–OR map as already settled should be treated as a hypothesis, not as current authority.
