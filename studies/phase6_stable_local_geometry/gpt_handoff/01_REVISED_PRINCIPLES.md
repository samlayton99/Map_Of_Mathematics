# 01 — Revised Principles

The review package’s principles should be retained, but two require refinement.

## 1. Functorial local growth, not global immobility

Let \(M_t\hookrightarrow M_{t+1}\) be an append-only library extension.

For any unchanged proof artifact \(p\),

\[
P_{t+1}(p)\cong P_t(p),
\]

where \(P_t(p)\) is its exact local typed move object.

This means the old local structure embeds unchanged into the new library.

It does **not** require all global statistics to remain fixed. It is legitimate for the following to evolve:

- citation counts;
- branch use;
- centrality;
- communities;
- learned relevance;
- global routing preferences.

Those are time-indexed fields over the stable core.

If an old proof is rewritten to use a new theorem, that is a new proof artifact/version. The old certificate can remain in history.

## 2. No arbitrary constants in the canonical structure

No fitted decimal should determine:

- whether an exact relation exists;
- the local typed role of an occurrence;
- the canonical local hierarchy;
- or a default structural filtration boundary.

But a learned neural navigator necessarily contains fitted real-valued parameters. That is acceptable if it is:

- a versioned model artifact;
- trained over stable features;
- evaluated separately;
- and never confused with the verified mathematical structure.

The rule is therefore:

> No fitted constants in the canonical graph or its intrinsic structural relations. Learned policies and dynamic global overlays are allowed as separate, versioned layers.

## 3. Preserve exact typed relations

Never collapse these into one undifferentiated dependency edge:

- theorem application;
- definition unfolding/folding;
- object construction;
- constructor/witness;
- local-hypothesis use;
- rewrite/transport;
- implicit argument;
- instance support;
- type/interface reference;
- generated/private helper;
- source-provenance-only reference.

## 4. Local salience is occurrence-relative

The same declaration can be:

- the content in one proof;
- supporting glue in another;
- background infrastructure in a third.

Permanent node-level “junk” labels cannot express this.

## 5. Global universality is dynamic

A declaration’s current breadth of use is a global, time-dependent property.

It may be useful for present-day navigation, but it must not redefine old local proof edges.

## 6. Depth is a stable coordinate, not a complete importance score

Preserve:

- target depth;
- cited depth;
- absolute depth drop;
- relative depth drop;
- interface/body depth separately.

Use depth to organize vertical scale and test self-similarity. Do not define importance as depth.

## 7. Ranking and inclusion remain separate

Local ranking or layering answers:

> Which moves should a proof expose first?

Inclusion and route policy answer:

> Which relation types and scales should this map view admit?

Graph entropy, components, and path length may help choose a view. They should not be fed back into local proof salience without independent evidence.

## 8. The canonical object should support multiple views

At minimum:

- proof-move view;
- definition/concept view;
- exact certificate view;
- infrastructure/provenance view;
- global usage view;
- state-conditioned applicability/search.

## 9. Validate independently

Never score a construction mainly by a “junk” mask derived from the same signals.

Standing independent checks should include:

- metamorphic/refactoring invariance;
- exact expansion/reconstruction;
- held-out prediction;
- module co-location only as a weak proxy;
- pairwise mathematical relatedness;
- concrete navigation tasks.

## 10. Self-similarity is a hypothesis

Seek approximate scale-stationarity across:

- target depth;
- proof size;
- mathematical area;
- library versions.

Do not force a fractal or stationary model if the data rejects it.

## 11. Do not optimize the flattened representation indefinitely

Before another large ranking search, test whether restoring the typed proof hierarchy removes the problem the ranking is compensating for.
